## 早先模拟案例：代码定位与验证

这是对话中的模拟案例，尚未创建案例文件，未在仓库中发现或修复这个问题。

**症状：** 修改昵称后接口成功，列表仍显示 Alice，刷新页面后显示 Bob。

**候选解释：** H1 后端未保存；H2 前端缓存过期；H3 数据已更新但组件未更新。

**观察证据：** 首次 GET 返回 Alice；PATCH 返回 Bob；保存后没有新 GET；刷新后 GET 返回 Bob。这降低了 H1 的可能性，但单凭请求记录还不能确认 H2。

**定位过程：** 读取 `onRename`，发现它在更新成功后调用 `loadUsers` 并渲染；继续读取 `loadUsers`，发现存在缓存时直接返回旧列表。由此形成“服务端更新 → 再次读取命中旧缓存 → 渲染旧数据”的因果链。

**候选修复：** 更新成功后使相应列表缓存失效，再加载。此简化方案用于讲解，不声称处理了所有并发请求和缓存竞态。

**有效验证：** 先加载以建立 Alice 缓存 → 经过页面改名流程 → 不刷新页面 → 断言显示 Bob。只验证后端能读到 Bob，会绕开故障路径。

**证据变化：** 如果保存后已经 GET 且返回 Bob，调查应转向组件状态和渲染路径，不能继续凭原症状修改缓存。

分析每一步时使用四个问题：

1. 正在验证哪个假设？
2. 此次工具调用能排除什么？
3. 补丁是否对应已有证据支持的因果链？
4. 验证能否暴露错误补丁，且修复前能够复现失败？

“信息增益”是教学中分析动作价值的视角，不代表 Codex 源码显式实现了该公式。

## 并发案例：清缓存后为何仍读到旧值

这是演示 8 的构造案例。症状为改名成功后，后台旧预取结束，再打开列表会恢复旧昵称；新建页面会话则正常。

候选解释包含服务端未保存、缓存未失效、视图未刷新，以及旧请求被复用或回写。实际证据为服务端快照已经是 Bob；仓库的改名流程已经执行 `cache = null`；事件却只有 GET(Alice) 开始 → PATCH 保存 Bob → GET 返回 Alice，没有改名后的新 GET。结合 `loadUsers` 在存在 `inFlight` 时直接复用，以及 `.then` 无条件回写缓存，定位到跨改名状态复用了旧请求。视图代码只是显示仓库返回值，无需修改。

Kimi 增加 `generation`：成功改名后推进版本；只复用同版本请求；只有请求版本仍为当前版本才允许写入缓存。`finally` 还检查 Promise 身份，避免旧请求清掉新请求标记。旧预取仍向其原调用者返回 Alice，但当前缓存和改名结果必须是 Bob，服务端 GET 快照语义保持原样。

新增回归明确观察到 GET(Alice) 开始 → PATCH 保存 Bob → GET(Bob) 开始并返回 → GET(Alice) 最后返回；之后缓存仍为 Bob。这比只断言服务端保存 Bob 更贴近故障路径。修复范围限于本例后台预取和仓库缓存，不声称覆盖所有界面并发更新问题。

这次 `shell` 工具本身返回成功，而修改前测试的 `exitCode` 是 1；工具执行成功不等于验证通过。Kimi 第一次实现就通过了预置验收，尚不能用本例声称观察到“错误功能补丁失败后修改假设”。

## 测试覆盖案例：测试能否排除错误补丁

延续上述并发案例，检查 Kimi 修复中的 `finally`：只有 `inFlight.promise === request` 才清空标记。双挂起请求实验验证了它的作用：A 属于旧版本，B 属于新版本；A 结束时，过期缓存写入已被 generation 阻止，但如果 A 无条件清理标记，尚未结束的 B 会被忘记，下一次读取便另起 C。数据最终仍可能是 Bob，所以只检查最终昵称的测试无法排除这个错误变体。

新用例将断言落在“同状态读取必须合并请求”的需求上：A、B 同时挂起 → A 结束 → 再次读取 → GET 次数仍为 2 → 释放 B 并核对 Bob。正确实现通过，无条件清理变体出现 `3 !== 2`。从已经通过的测试出发构造错误变体，再用新场景区分它们，可以具体发现测试覆盖不足，而无需假定“全绿就满足全部要求”。

## 最近总结：模型、工具与 harness

2026-11-15 用户追问 Coding Agent 的核心是否就是提供工具，再加额外 harness 工程。已区分：本项目大部分源码确实在实现程序侧的工具接入与 harness；完整 Agent 还依赖模型自身的代码理解、推理和工具使用能力。`runLoop` 把上下文与工具交给 Provider，再执行并回传结果，没有写死“这个任务先读哪个文件、怎样判断根因”的通用解题流程。

这里的 harness 包括循环、上下文与指令组织、工具执行和反馈，也包含权限、预算、日志和恢复；不能把它全部视为可有可无的外围工程。工具规定可做的动作，模型选择动作，harness 影响模型看到的信息、可执行的边界与结果反馈。此前 generation 等并发算法属于被修复的业务程序，用于观察求解与验证过程，不是 Coding Agent 本体的算法。本轮只做概念归纳，未新增模型调用或实验。
